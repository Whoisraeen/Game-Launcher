# Bug Tracker for Game Launcher

This file documents potential bugs, gaps, and logical concerns identified from the **Game Launcher Features** specification.  Each entry is meant to guide testing, implementation, and future development.

---

| ID | Feature Category | Description of Issue | Severity | Status | Suggested Fix / Audit Note |
|----|-------------------|----------------------|----------|--------|---------------|
| **BUG-001** | Core Library Integration | Universal game library may not correctly handle authentication tokens for each platform (Steam, Epic, GOG, Origin, Uplay, Battle.net). Missing token refresh could cause launch failures. | High | Open | Implement a unified token manager that stores, refreshes, and securely retrieves each platform’s credentials. |
| **BUG-002** | Platform Detection | One‑click launch relies on automatic platform detection. Edge cases exist where the same game exists on multiple platforms (e.g., Steam and Epic). The launcher may pick the wrong executable. | Medium | Open | Provide a disambiguation UI when duplicate titles are detected, allowing the user to select the preferred platform. |
| **BUG-003** | Custom Categories & Tagging | Tags are stored locally but not synced with cloud. Deleting a tag in one device can leave orphaned references on another. | Low | Open | Add a cleanup routine that validates tag references on startup and removes stale links. |
| **BUG-004** | Advanced Search & Filtering | Filtering by “multiplayer type” assumes a static list of types. New multiplayer modes (e.g., co‑op PvE) are not recognized, causing filter errors. | Medium | Open | Make the filter list extensible via a configuration file or UI‑driven addition. |
| **BUG-005** | Drag‑and‑Drop Organization | Drag‑and‑drop rearrangement does not persist order across sessions when the library is sorted by another criterion (e.g., alphabetically). | Medium | Open | Store a per‑game “custom order” index and apply it after any sort operation. |
| **BUG-006** | Hide/Archive Feature | Archived games are still counted in achievement aggregation and play‑time statistics, leading to inaccurate totals. | High | Open | Exclude archived entries from all aggregate calculations and provide a toggle to include them if desired. |
| **BUG-007** | Deep Integration – Mod Parameters | Launch parameters for mods are concatenated without proper quoting, breaking games that require spaces in arguments. | High | Open | Use a robust argument‑builder that correctly escapes and quotes each parameter. |
| **BUG-008** | Achievement Tracking | Achievements from different platforms use different ID schemes; duplicate IDs may collide in the unified view. | Medium | Partially Verified | **Audit Note:** DB uses `uuid` and keyed `(platform, platform_achievement_id)` preventing DB collisions, but UI may still lack source platform distinction. |
| **BUG-009** | Cross‑Platform Friends List | Some platforms (e.g., GOG) do not expose an API for friend status, yet the UI still attempts to display it, causing errors. | Medium | Invalid | **Audit Note:** Feature is fully mocked (`FriendsManager.ts` seeds fake users). No real cross-platform API logic exists yet. |
| **BUG-010** | News & Updates Feed | Feed aggregates RSS/JSON from multiple sources without rate‑limiting; rapid refresh can hit API throttling limits. | Low | Open | Implement exponential back‑off and cache responses for a configurable interval. |
| **BUG-011** | Play‑Next Recommender | Recommendation engine only considers *genre*; ignores play‑time and friend activity, leading to irrelevant suggestions. | Low | Open | Extend the algorithm to weight play‑time, recent sessions, and friends’ recent plays. |
| **BUG-012** | Performance Integration – Pre‑launch Optimizer | The optimizer attempts to close processes based on a hard‑coded whitelist. New background apps (e.g., Discord) are not recognized and remain running, affecting FPS. | Medium | Verified | **Audit Note:** Verified in `ProcessManager.ts`. `SYSTEM_SAFELIST` is entirely hardcoded. Need dynamic UI config. |
| **BUG-013** | Graphics Settings Profiles | Profiles are stored per‑game but do not migrate when the game is renamed or moved to a different library path. | Medium | Open | Store profiles using a unique game identifier (e.g., Steam AppID) rather than the file name/path. |
| **BUG-014** | Performance Overlay | Overlay draws over DirectX fullscreen games but can cause flickering on multi‑monitor setups. | High | Open | Detect the active monitor and render the overlay only on the primary display, or use a detachable overlay window. |
| **BUG-015** | Post‑game Reports | Reports are generated asynchronously; if the user shuts down the launcher immediately after exiting a game, the report may be lost. | Low | Open | Queue the report generation and persist it to disk before the launcher exits. |
| **BUG-016** | Memory Cleaner | Cleaner runs on a timer but does not respect games that dynamically allocate large memory during runtime, leading to premature memory releases and crashes. | High | Partially Verified | **Audit Note:** Memory cleaner runs specifically *after* session exit, but dynamic resource allocator runs on a timer. |
| **BUG-017** | Social Feed – Friend Activity | Feed assumes a unified timestamp format; services return epoch, ISO‑8601, or localized strings, causing sorting errors. | Medium | Open | Normalize all timestamps to UTC ISO‑8601 upon ingestion. |
| **BUG-018** | Screenshot Gallery | Automatic detection uses window titles; games that hide the title bar are missed, resulting in incomplete galleries. | Low | Open | Add a fallback that monitors DirectX/GL capture buffers directly. |
| **BUG-019** | Shared Collections | When sharing a collection, the recipient may not have some games, causing broken links in the UI. | Medium | Open | Show placeholders for missing games and offer an “add to library” prompt. |
| **BUG-020** | Custom Backgrounds | Background images are loaded without size validation, leading to OOM crashes on low‑memory systems. | High | Verified | **Audit Note:** Verified in `App.tsx`. Background image src is set directly without pre-processing or size checks. |
| **BUG-021** | Dynamic Themes | Theme switch triggers a full UI reload, briefly freezing the app for large libraries. | Medium | Open | Implement incremental theme updates that only repaint changed components. |
| **BUG-022** | Animated Wallpapers | Animation loop runs on the UI thread, degrading input responsiveness during gameplay launch. | High | Open | Move animation rendering to a WebWorker/Off‑screen canvas thread. |
| **BUG-023** | AI Recommendation Engine | The engine requires internet access; offline mode falls back to an empty list, confusing users. | Low | Open | Cache the last successful recommendation set and use it when offline. |
| **BUG-024** | Automatic Game Updates | Update scheduler runs at startup; if the launcher is launched during a Windows Update, it may deadlock on network resources. | Medium | Invalid | **Audit Note:** Checked `updateManagerService.ts`. Updates are detected via local manifest parsing, not active network downloads. |
| **BUG-025** | Smart Notifications | Notification throttling logic resets on each app launch, leading to duplicate alerts for the same event. | Low | Open | Persist the last‑sent notification timestamps to a local store. |
| **BUG-026** | Quick Play Mode | Random selection does not filter out archived or hidden games, occasionally launching an unwanted title. | Medium | Open | Apply the same visibility filters used by the library view before picking a random game. |
| **BUG-027** | Completion Tracking | Personal rating system stores values as integers but UI displays a star rating with half‑star precision, causing rounding inconsistencies. | Low | Verified | **Audit Note:** Confirmed in `migrator.ts`. Ratings are stored as `INTEGER DEFAULT 0`, making float handling impossible. |
| **BUG-028** | Backlog Manager | Priority levels are stored as strings; sorting treats them lexicographically (`High`, `Low`, `Medium`) yielding incorrect order. | Medium | Verified | **Audit Note:** Confirmed in DB schema. Priority is `TEXT DEFAULT 'normal'`. |
| **BUG-029** | Playtime Goals | Goal progress resets when the user changes the library path (e.g., moves to a new SSD). | Medium | Open | Store goal data independently of the library location and migrate on path change. |
| **BUG-030** | Premium Themes Marketplace | Marketplace metadata validation is missing; malformed JSON from a theme can crash the theme loader. | High | Open | Validate theme manifests against a schema before applying them. |
| **BUG-031** | Cloud Sync Settings | Sync performs a full overwrite; concurrent edits on two machines cause last‑write‑wins loss of data. | High | Open | Implement conflict detection with merge prompts or version stamping. |
| **BUG-032** | Game Performance Optimizer | Auto‑adjusts settings based on detected hardware but does not account for user‑defined caps, potentially lowering graphics beyond user preference. | Medium | Open | Add a user‑configurable maximum quality level that the optimizer respects. |
| **BUG-033** | RGB Lighting Controller | Sends commands to multiple vendor SDKs sequentially; a slow SDK blocks the others, causing delayed lighting changes. | Low | Open | Dispatch SDK calls asynchronously and handle individual failures gracefully. |
| **BUG-034** | Shader Cache Cleaner | Cache size calculation does not include hidden files, underreporting actual usage and leaving large caches uncleared. | Medium | Invalid | **Audit Note:** The Shader Cache UI uses mock data and has no backend implementation. |
| **BUG-035** | Pre‑Game Health Check | Temperature thresholds are hard‑coded; on newer GPUs the safe limits differ, leading to false warnings. | Medium | Verified | **Audit Note:** Confirmed in `healthCheckService.ts`. `cpuCritical > 85` and `gpuCritical > 85` are hardcoded. |
| **BUG-036** | Crash Analyzer | Parses Windows Event Logs but does not handle Unicode characters, causing parsing failures on localized systems. | High | Verified | **Audit Note:** `execAsync` via Node for `wevtutil` defaults to OEM codepage decoding instead of `chcp 65001`, garbling Unicode. |
| **BUG-037** | Mod Manager | Automatic conflict detection only checks file name collisions, missing deeper conflicts such as overlapping asset IDs. | High | Verified | **Audit Note:** Confirmed in `modManager.ts`. `checkConflicts()` only checks for exact file path collisions. |
| **BUG-038** | Controller Mapper ++ | Profiles are saved per‑user but not per‑game; switching games does not automatically load the appropriate mapping, confusing users. | Medium | Invalid | **Audit Note:** No per-game controller mapping feature exists. `GamepadMapper` only maps inputs to UI navigation. |
| **BUG-039** | Streaming Overlay Generator | Overlay templates are stored in a flat folder; naming collisions can overwrite user‑created templates inadvertently. | Low | Invalid | **Audit Note:** Overlays are generated dynamically as HTML blobs in `StreamOverlays.tsx`. There is no local template saving. |
| **BUG-040** | Esports Tournament Tracker | Notification timestamps are stored in local time; users across time zones receive alerts at incorrect moments. | Medium | Invalid | **Audit Note:** This feature does not exist in the codebase. |
| **BUG-041** | Network Optimizer | Ping test parsing (`Average = (\d+)ms`) hardcodes English, French, and German output string matching. This causes parsing to fail and return `-1` on any other OS locale. | High | Verified | **Audit Note:** Discovered in `networkService.ts`. Must use locale-agnostic ping options or regex fallbacks. |
| **BUG-042** | Screenshot Manager | Directory scanner assigns a completely random UUID to screenshots *every time* it runs, matching solely by exact file path. If a file is moved or renamed, it generates a new database entry and orphans old metadata (tags, favorites, captions). | High | Verified | **Audit Note:** Discovered in `screenshotService.ts`. Needs content hashing or persistent metadata sidecar files. |
| **BUG-043** | Cloud Save Manager | Auto-backup completion calls `uuidv4()` to generate a backup ID, but `uuidv4` is never imported in the file. This causes auto-backups to silently crash or throw a ReferenceError right after archiving completes. | Critical | Verified | **Audit Note:** Discovered in `SaveManagerService.ts`. Simple missing import that breaks core functionality. |
| **BUG-044** | Hardware Monitor | The monitor loop invokes `si.fsSize()` (heavy filesystem scanning) every 10 seconds within the `getStats()` polling loop. This causes unnecessary disk I/O and potential micro-stuttering during gameplay. | High | Verified | **Audit Note:** Discovered in `hardwareMonitor.ts`. Disk space checks should be cached or polled much less frequently than CPU/GPU metrics. |
| **BUG-045** | Playtime Tracker | The tracker strictly checks `isProcessRunning` against the launched executable name. If a game uses a launcher that exits immediately after spawning the actual game process, playtime tracking stops instantly. | High | Verified | **Audit Note:** Discovered in `playtimeTracker.ts` and `processManager.ts`. Need parent-child PID tracking rather than simple executable name checks. |
| **BUG-046** | Cloud / Auth Service | `supabaseService.ts` hardcodes the Supabase URL and anon key as string literals on lines 6-7. These credentials are committed to the git repository, allowing anyone with repo access to query the backend directly and potentially enumerate users or data. | Critical | Verified | **Audit Note:** Hardcoded `SUPABASE_URL` and `SUPABASE_ANON_KEY` in source. Must move to `.env` and ensure `.env` is in `.gitignore`. |
| **BUG-047** | Price Tracker | `priceTrackerService.ts` `checkPrices()` is `async` but calls `this.getAllWishlistGames()` which uses synchronous `getDb()` on the main thread. Meanwhile, `this.updatePrice()` also calls synchronous `getDb()`. The `checkPrices` loop serializes network + DB calls per-game with a 1s delay each, meaning a large wishlist (100+ games) will block the price check for 100+ seconds. | Medium | Verified | **Audit Note:** Needs batched DB updates and parallel network requests with concurrency limiting. |
| **BUG-048** | Expense Tracker | `expenseTrackerService.ts` `importFromLibrary()` fabricates purchase prices (`$29.99` for Steam/Epic/GOG, `$9.99` for itch.io) for all library games. These fabricated numbers are stored as real purchase records with `source: 'import'`, silently corrupting the user's actual expense data with inaccurate totals. | High | Verified | **Audit Note:** Discovered in `expenseTrackerService.ts` lines 254-262. Should prompt user for actual prices or flag estimates clearly. |
| **BUG-049** | Game Manager – Launch | `gameManager.ts` `launchGame()` instantiates a new `SettingsManager()` twice (lines 548 and 579) inside the same function call. Each instantiation re-reads the entire settings table from disk. Should reuse a single instance. | Low | Verified | **Audit Note:** Minor performance waste from redundant DB reads on every game launch. |
| **BUG-050** | Game Manager – Command Injection | `gameManager.ts` passes `game.executable` and `launchOptions` directly into `exec()` on lines 609, 621-622, 652, and 654 without any sanitization. A malicious game entry with shell metacharacters in its path or launch options could execute arbitrary commands. | Critical | Verified | **Audit Note:** Must use `execFile()` or `spawn()` with argument arrays instead of string interpolation into `exec()`. |
| **BUG-051** | Process Manager – Memory Cleanup | `processManager.ts` `cleanMemoryAfterSession()` sets `$p.MinWorkingSet = 1; $p.MaxWorkingSet = 1` on background processes (line 206). Setting MaxWorkingSet to 1 byte can cause immediate page-thrashing and application crashes for those processes, not just graceful memory release. | High | Verified | **Audit Note:** Should use `SetProcessWorkingSetSize(-1, -1)` pattern via EmptyWorkingSet instead of forcing to 1 byte. |
| **BUG-052** | Fan Control Service | `FanControlService.ts` constructor unconditionally starts the `startControlLoop()` 5-second interval (line 14). Even when `FanControl.exe` does not exist, the loop runs every 5 seconds, spawning a process, failing, and returning mock data — doing useless work for the entire lifetime of the app. | Medium | Verified | **Audit Note:** Loop should only start when a fan curve is actually configured and the binary exists. |
| **BUG-053** | RGB Service – Async Leak | `RGBService.ts` effects like `startBreathingEffect()` (line 108) and `startColorCycle()` (line 131) run `await this.applyColor()` inside a `setInterval`. If `applyColor` takes longer than the interval period (50ms), callbacks will stack and queue, potentially flooding the OpenRGB server with overlapping LED update commands. | Medium | Verified | **Audit Note:** Need a guard flag or use `setTimeout` chaining instead of `setInterval` to prevent overlapping async calls. |
| **BUG-054** | Audio Service | `audioService.ts` `getDevicesViaPowerShell()` marks `isDefault: idx === 0` (line 53), blindly assuming the first device returned by `Win32_SoundDevice` is the default. The WMI query does not guarantee default-device ordering, so the wrong device will appear as "default" in the UI. | Medium | Verified | **Audit Note:** Must query the actual default audio device via `Get-AudioDevice` or cross-reference with the default endpoint. |
| **BUG-055** | Audio Service – Injection | `audioService.ts` `setDefault()` passes `deviceId` directly into a PowerShell string template (line 78): `Set-AudioDevice -ID '${deviceId}'`. A malicious or malformed `deviceId` containing a single-quote could break out of the string and execute arbitrary PowerShell. | High | Verified | **Audit Note:** Must sanitize `deviceId` or use parameterized execution. |
| **BUG-056** | DLC Tracker – N+1 API | `dlcTrackerService.ts` `scanSteamDLCs()` makes one HTTP request per DLC ID (lines 112-115) with a 1-second delay between each. A game like "The Sims 4" with 60+ DLCs will take over a minute of serial API calls, blocking the scanner. | Medium | Verified | **Audit Note:** Should batch DLC lookups or at minimum fetch DLC details in parallel with a concurrency limit. |
| **BUG-057** | Friends Manager – VDF Parsing | `friendsManager.ts` `extractFriendsFromVdf()` uses a regex on a 50KB substring (line 397) to find `"name" "X"` pairs. The VDF format is hierarchical, so this regex also captures non-friend `"name"` keys from other config sections (e.g., game names, Steam categories), polluting the friends list with garbage entries. | High | Verified | **Audit Note:** Needs a proper VDF parser or at least depth-aware block detection instead of a flat regex scan. |
| **BUG-058** | Gaming Session Service | `gamingSessionService.ts` `createSession()` inserts `break_interval` at column index 10 (line 94) but the INSERT statement only has 10 value placeholders (line 83). The `break_interval` value is silently inserted as the `created_at` value, meaning sessions get the wrong creation time and lose their break interval setting. | High | Verified | **Audit Note:** The `VALUES` clause has 10 `?` markers but `break_interval` is passed as the 10th arg where `created_at` should go, and `break_interval` column is never populated. |
| **BUG-059** | Recommendation Manager – Tags Crash | `recommendationManager.ts` `getSmartSuggestion()` casts `g.tags` to `string[]` at line 37 and calls `.some()` on it. But `parseGames()` may return `[]` (empty array) which is fine, however if `JSON.parse` of `tags` fails (malformed JSON in DB), the `catch` in `parseGames` returns `[]` for the entire games array, silently discarding all games. | Medium | Verified | **Audit Note:** Error handling should be per-game, not all-or-nothing. A single corrupt tag entry kills all recommendations. |
| **BUG-060** | Supabase Service – Public URL on Private Bucket | `supabaseService.ts` calls `this.client.storage.from('game-saves').getPublicUrl(storagePath)` (lines 297-299) to generate a URL for uploaded save files. If the `game-saves` bucket has RLS/private access policies, the returned public URL will be a 403/404 for the user, silently breaking cloud save downloads. | High | Verified | **Audit Note:** Should use `createSignedUrl()` for private buckets instead of `getPublicUrl()`. |

| **BUG-061** | Video Editor – Remote Code Execution | `VideoEditorService.ts` line 42 uses `eval(videoStream.avg_frame_rate)` to calculate FPS from a string like `"30000/1001"`. `eval()` on untrusted data from an FFprobe response is a critical RCE vector — a maliciously crafted video file could embed arbitrary JavaScript in its metadata. | Critical | Verified | **Audit Note:** Must replace `eval()` with a safe arithmetic parser or simple string split: `const [n, d] = str.split('/'); return n/d;`. |
| **BUG-062** | Electron Main – Web Security Disabled | `main.ts` line 132 sets `webSecurity: false` in BrowserWindow webPreferences. This globally disables the Same-Origin Policy for the renderer process, allowing any loaded content (including injected scripts or malicious game metadata) to make cross-origin requests and read local files. | Critical | Verified | **Audit Note:** Must remove `webSecurity: false` and use Electron's `protocol.registerFileProtocol` or `net.fetch` to serve local images safely. |
| **BUG-063** | Drive Scanner – Command Injection | `DriveScanner.ts` line 189 passes `srcPath` and `destPath` directly into `execAsync(`robocopy "${srcPath}" "${destPath}" ...`)`. A game with a crafted install path containing `"` or shell metacharacters could inject commands into the robocopy call. | High | Verified | **Audit Note:** Must use `execFile()` with argument arrays or validate/sanitize paths before interpolation. |
| **BUG-064** | Compatibility Service – Registry Injection | `compatibilityService.ts` lines 77, 125, 130 pass `executablePath` directly into `reg query` and `reg add` commands. A malicious executable path value with embedded quotes or `&&` could execute arbitrary registry commands or shell payloads. | High | Verified | **Audit Note:** Must validate/sanitize `executablePath` before embedding in shell commands, or use a Node registry module. |
| **BUG-065** | Metadata Fetcher – IGDB Query Injection | `metadataFetcher.ts` lines 107, 198-200 embed user search queries directly into IGDB API body strings: `search "${title}";`. A title containing `";` could inject arbitrary IGDB query language commands. | Medium | Verified | **Audit Note:** Must escape double-quotes in the title before embedding, or use IGDB's parameterized search API. |
| **BUG-066** | Discord Manager – Hardcoded Client ID | `discordManager.ts` line 3 hardcodes `CLIENT_ID = '1344426698654224445'` with a comment saying it's a placeholder. If this ID doesn't match a registered Discord application, RPC login will always fail, and the singleton constructor silently swallows the error, making Discord presence permanently broken with no user feedback. | Medium | Verified | **Audit Note:** Should read from settings/env and surface a clear error to the UI when connection fails. |
| **BUG-067** | Auth Manager – Promise Leak | `AuthManager.ts` `loginSteam()` (line 22) returns `Promise<boolean>` but if the user navigates through Steam login without hitting a profile URL, the promise never resolves — it stays pending forever. The `closed` event resolves it, but if the window crashes instead of closing cleanly, the caller's `await` hangs permanently. | Medium | Verified | **Audit Note:** Add a timeout and error handler for `webContents` crash events to ensure the promise always resolves. |
| **BUG-068** | Hardware Compat – VRAM Unit Mismatch | `hardwareCompatService.ts` line 185: `gpuVerdict = judge(primaryGpuVram, reqs.minVramMb, reqs.recVramMb)`. `primaryGpuVram` comes from `systeminformation` which returns VRAM in MB, but the `judge()` function compares it against `minVramMb`/`recVramMb` which the DB defaults to `1024`/`2048`. This is fine if units match, but `si.graphics().controllers[].vram` can return 0 on some systems (integrated GPUs), causing every game to show "Below Minimum" GPU compatibility. | Low | Verified | **Audit Note:** Missing handling for `vram === 0` case (common on Intel iGPUs). Should return "Unknown" instead of "Below Minimum". |
| **BUG-069** | News Manager – Regex RSS Parser | `newsManager.ts` `parseRSS()` uses regex to parse XML (lines 49-59). This fails on RSS feeds that use nested CDATA, namespaced tags (e.g., `<content:encoded>`), or Atom format. The description regex can also match greedily across multiple items if CDATA sections span multiple lines. | Medium | Verified | **Audit Note:** Should use a proper XML parser (e.g., `fast-xml-parser`) instead of regex for reliable RSS/Atom parsing. |
| **BUG-070** | Emulation Service – Command Injection | `EmulationService.ts` `getLaunchCommand()` line 185 builds a shell command: `"${emulator.executable}" ${args}`. Both the emulator path and ROM path are user-provided strings that are string-interpolated without sanitization. A ROM file with shell metacharacters in its name could execute arbitrary commands. | High | Verified | **Audit Note:** Same class of bug as BUG-050. Must use `execFile()` or `spawn()` with argument arrays. |
| **BUG-071** | OBS Service – Connect Race Condition | `ObsService.ts` `connect()` line 68 sets `this.isConnected = true` immediately after `await this.obs.connect()`, but the `ConnectionOpened` event listener on line 30 also sets `this.isConnected = true`. If `disconnect()` is called between the `connect()` promise resolution and the `ConnectionOpened` event, the state becomes inconsistent — `isConnected` flips to `true` after the user intended to disconnect. | Low | Verified | **Audit Note:** Should manage connection state through the event listeners only, not duplicate it in the `connect()` method. |
| **BUG-072** | Settings Manager – Numeric String Coercion | `settingsManager.ts` line 124: `if (!isNaN(Number(val)) && val !== '') val = Number(val)`. This converts ALL numeric-looking strings to numbers, including hex color strings like `'#4f46e5'` (which `Number()` returns NaN for, so safe), but the Steam API key `'123456789'` will be coerced from string `"123456789"` to number `123456789`, breaking any string comparison or API call using it. | Medium | Verified | **Audit Note:** Must only coerce known numeric settings (opacity, targetFps, etc.) rather than applying blanket conversion. |
| **BUG-073** | Drive Scanner – Drive Type Fallback | `DriveScanner.ts` lines 78-82: When a drive's type is "Unknown", the code picks the *first non-Unknown type from any drive* as a fallback. This means if you have one NVMe and one HDD, the HDD will incorrectly be labeled as "NVMe" (or vice versa), displaying wrong drive type information in the UI. | Low | Verified | **Audit Note:** The fallback should be removed; if the drive type can't be determined, leave it as "Unknown" rather than guessing from other drives. |

*All entries are initial observations.  Further testing may reveal additional nuances.*
